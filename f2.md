# Codex Task: Clean All Microservices Boundaries

## Goal

Review and clean the entire CreatorDeal CRM microservices project.

The previous split from monolith to microservices copied some entities into the wrong services. We need to enforce clean microservice ownership.

Each service must only contain its own domain files and must not contain copied monolith entities from other services.

---

# Target Services

The project should contain:

```text
creator-service
brand-service
deal-service
invoice-service
notification-service
```

No Config Server, Eureka Server, or API Gateway yet.

# Global Rule: No Cross-Service JPA Relations

Search the entire project for:

```java
@ManyToOne
@OneToOne
@OneToMany
@JoinColumn
```

Review every occurrence.

Allowed JPA relationship:

```text
deal-service:
DealDeliverable -> Deal
```

All other cross-service relationships must be removed.

External service references must be plain IDs:

```java
private Long creatorId;
private Long brandId;
private Long dealId;
private Long invoiceId;
```

---

# Package Cleanup Rule

Each service package must match its service.

Examples:

```text
com.creatordeal.creatorservice
com.creatordeal.brandservice
com.creatordeal.dealservice
com.creatordeal.invoiceservice
com.creatordeal.notificationservice
```

No service should import another service package.

For example, this is wrong:

```java
import com.creatordeal.brandservice.entity.Deal;
```

This is also wrong:

```java
import com.creatordeal.dealservice.entity.Creator;
```

Search for:

```text
com.creatordeal.creatorservice
com.creatordeal.brandservice
com.creatordeal.dealservice
com.creatordeal.invoiceservice
com.creatordeal.notificationservice
```

inside each service and remove wrong imports.

# Repository Method Cleanup

If entity stores plain IDs, repository methods should be simple.

Examples:

## brand-service

```java
List<Brand> findByCreatorId(Long creatorId);
```

## deal-service

```java
List<Deal> findByCreatorId(Long creatorId);
List<Deal> findByBrandId(Long brandId);
```

## invoice-service

```java
Optional<Invoice> findByDealId(Long dealId);
List<Invoice> findByCreatorId(Long creatorId);
List<Invoice> findByCreatorIdAndStatus(Long creatorId, InvoiceStatus status);
```

## notification-service

```java
List<Reminder> findByCreatorId(Long creatorId);
List<Reminder> findByCreatorIdAndStatus(Long creatorId, ReminderStatus status);
```

Do not use relation navigation like this unless relation is inside same service:

```java
findByCreator_Id
findByBrand_Id
findByInvoice_Id
```

Exception:

```java
deal-service DealDeliverableRepository can use:
findByDeal_Id(Long dealId)
```

because Deliverable and Deal are in the same service.

# DTO Cleanup Rule

Responses should return IDs only for external resources.

Example BrandResponse:

```java
private Long id;
private Long creatorId;
private String brandName;
```

Do not return:

```java
creatorName
```

unless the service calls creator-service explicitly. We are not doing that yet.

Example DealResponse:

```java
private Long id;
private Long creatorId;
private Long brandId;
```

Do not return:

```java
creatorName
brandName
```

Example InvoiceResponse:

```java
private Long id;
private Long dealId;
private Long creatorId;
```

Do not return:

```java
dealTitle
creatorName
```

Example ReminderResponse:

```java
private Long id;
private Long creatorId;
private Long dealId;
private Long invoiceId;
```

Do not return:

```java
dealTitle
invoiceNumber
creatorName
```

unless explicitly stored locally or fetched using another service later.

---

# Mapper Cleanup Rule

Because DTOs return IDs only, mappers must not call removed relations.

Remove code like:

```java
deal.getCreator().getId()
deal.getCreator().getDisplayName()
deal.getBrand().getBrandName()
invoice.getDeal().getTitle()
reminder.getInvoice().getInvoiceNumber()
```

Use:

```java
deal.getCreatorId()
deal.getBrandId()
invoice.getDealId()
invoice.getCreatorId()
reminder.getDealId()
reminder.getInvoiceId()
```

# Reminder Consumer Cleanup

Notification service event consumers should create Reminder using IDs only.

Correct:

```java
Reminder.builder()
    .creatorId(event.creatorId())
    .dealId(event.dealId())
    .invoiceId(event.invoiceId())
    .reminderType(ReminderType.INVOICE_DUE)
    .scheduledAt(event.dueDate().atTime(9, 0))
    .status(ReminderStatus.PENDING)
    .build();
```

Wrong:

```java
reminder.setDeal(deal);
reminder.setInvoice(invoice);
```
